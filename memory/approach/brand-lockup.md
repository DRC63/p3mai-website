# P3MAI brand lockup — the wordmark rule

**Status:** Enforced everywhere as of 6 August 2026.

## The rule

The wordmark is **two-tone**: `P3M` in the primary colour, **`AI` in gold**. It is never rendered
as a single flat colour. The gold `AI` is the whole point of the name — Programme, Project and
PMO Management **in AI**.

| Context | P3M | AI |
|---|---|---|
| Light background | navy `#0B2545` | gold `#C9A227` |
| Dark background | white `#ffffff` | gold `#C9A227` |
| Themed pages | theme ink variable | gold variable |

## How it is implemented

**HTML** — the canonical form, defined in `style.css`:

```html
<span class="logo-text">P3M<span class="brand-ai">AI</span></span>
```
```css
.logo-text .brand-ai { color: var(--color-accent); }
```

**The pyramid and the wordmark are separate.** `logo-triangle-navy.svg`,
`logo-triangle-white.svg` and `logo-navy.svg` are **icon-only** — a 100×100 gradient pyramid with
no text. The wordmark always comes from HTML text beside the image. Do not look for a wordmark
inside those files; it is not there.

**SVG** (only where HTML text is not possible) — split with tspans:
```xml
<tspan fill="#ffffff">P3M</tspan><tspan fill="#C9A227">AI</tspan>
```

**Word / PowerPoint** — the brand PNGs are generated by `tools/brand-assets.py`, which draws
`P3M`, measures its bounding box, then places `AI` at `bb.x1 - bb.width*0.105`. The correction
factor removes the trailing side-bearing that otherwise leaves a visible gap. **If you change the
font size, re-check that factor visually** — it is empirical, not derived.

**Email addresses** count too: `drcolvin@P3M<span class="brand-ai">AI</span>.com`.

## Where it applies

- All five site pages — header and footer lockups
- Both cost estimators — brand bar, quote email, footnote link
- `calculator.html` — email address
- `logo-white.svg` — tspan split
- `P3MAI-Portfolio/roadmap-visual.html` — masthead eyebrow (theme-variable version)
- `brand_cover.png`, `brand_header.png`, `brand_footer.png` — the Word/PowerPoint assets,
  regenerated from `tools/brand-assets.py` (tracked; the document builder that consumes them
  lives in the gitignored `reference/build/`)

## How to audit it

Run this from the folder above the projects. Any file with a flat wordmark shows a non-zero count
in the right-hand column:

```bash
for f in $(find business-website P3MAI-Portfolio -maxdepth 2 \( -name "*.html" -o -name "*.svg" \)); do
  b=$(grep -o 'brand-ai' "$f" | wc -l)
  p=$(grep -oE '>P3MAI<|>P3MAI</text>' "$f" | wc -l)
  [ "$b" -gt 0 ] || [ "$p" -gt 0 ] && printf "%-55s %-4s %s\n" "$f" "$b" "$p"
done
```

**Caution when writing audits like this:** restrict the search to the markup (everything before
`<script>`). JavaScript selector strings such as `input[name="poti"]:checked` will otherwise match
attribute patterns and produce false failures — this happened once already.
